# LabDNS 1.2.0 Release Notes

Release date: 2026-08-23
Previous release: [v1.1.1](https://github.com/hilather/go-lab-dns/blob/v1.1.1/docs/releases/v1.1.1.md)
Application version: 1.2.0
Configuration versions: labdns.dev/v1alpha1
REST versions: /v1
MCP protocol versions: 2026-07-28 (default pin; optional overlay skip)
Container digest: unpublished (image build and digest pin follow this tag)

These notes are curated. They are not a commit list. They cover every functionality difference from [v1.1.1](https://github.com/hilather/go-lab-dns/blob/v1.1.1/docs/releases/v1.1.1.md).

## Highlights

Desired-state DNS names are no longer rejected solely because a label is longer than 63 octets or the presentation FQDN is longer than 254 characters. Lab and QA documents can store over-length owners (and other configured names) as lower-case FQDNs with a trailing dot; local/management resolve returns the configured RRset. RFC 1035 wire maxima still apply to UDP/TCP messages: LabDNS does not emit malformed packets ([ADR 0007](https://github.com/hilather/go-lab-dns/blob/v1.2.0/docs/adr/0007-defer-unsafe-wire-chaos.md), [ADR 0009](https://github.com/hilather/go-lab-dns/blob/v1.2.0/docs/adr/0009-accept-overlength-desired-state-names.md)).

## Added

- [ADR 0009](https://github.com/hilather/go-lab-dns/blob/v1.2.0/docs/adr/0009-accept-overlength-desired-state-names.md): accept over-length DNS names in desired state. No new schema field and no flag to restore the old length checks.

## Changed

- `config.CanonicalName` / `checkDNSName` no longer apply a 63-octet label cap or a 254-character presentation FQDN cap. The shared path covers zone name, record owner, SOA names, nameservers, forwarding suffix, chaos protected/scope owners, and name tokens inside MX/SRV/SVCB/HTTPS RDATA.
- JSON Schema `$defs.name` description records that RFC 1035 wire maxima are not applied as `maxLength` ([api/jsonschema/labdns.dev.v1alpha1.json](https://github.com/hilather/go-lab-dns/blob/v1.2.0/api/jsonschema/labdns.dev.v1alpha1.json)). Canonical JSON of previously valid documents is unchanged.

## Removed or deprecated

- None.

## Security

- No authentication, authorization, or TLS changes. Over-length names remain ASCII LDH+underscore (plus leftmost `*`). Non-ASCII names are still rejected. The 1 MiB document cap is unchanged. Wire encoding still refuses illegal length prefixes (ADR 0007).

## DNS behavior

- Local/management resolve of an exact over-length owner and type returns the configured RRset (not NXDOMAIN/NODATA).
- UDP/TCP parse and encode still follow RFC 1035: incoming QNAMEs with labels longer than 63 octets or a wire name longer than 255 octets cannot be unpacked; answers cannot pack those owners. Management `resolve` / `explain` is the supported query path for those names.
- Non-length name syntax is unchanged: empty name, empty label, non-ASCII, characters outside `a-z` `0-9` `-` `_` (and leftmost `*`), labels that start or end with `-`, and `*` that is not the leftmost label still fail validation.

## Chaos behavior

- Unchanged. Chaos protected-name and scope-owner strings go through the same canonicalization, so they may now be over-length; protected-name matching and emergency disable are otherwise the same.

## REST API

- Unchanged paths and schemas. Plan/apply of over-length names now succeeds because adapters share `config.CanonicalName`. No new endpoints.

## MCP API and protocol compatibility

- Unchanged. Default remains **2026-07-28 only**. SDK remains `github.com/modelcontextprotocol/go-sdk v1.7.0`. No new tools. State-changing tools accept over-length names via the same application path as REST.
- Manifest: [api/mcp/v1.json](https://github.com/hilather/go-lab-dns/blob/v1.2.0/api/mcp/v1.json) (unchanged).

## Configuration and schema

- Validation of `labdns.dev/v1alpha1` names no longer fails for length alone. Schema: [api/jsonschema/labdns.dev.v1alpha1.json](https://github.com/hilather/go-lab-dns/blob/v1.2.0/api/jsonschema/labdns.dev.v1alpha1.json) (`$defs.name` description; still no `maxLength`).
- Defaults, IDs, durations, CNAME coexistence, wildcard NS/DNAME, and document size are unchanged.
- Configuration versions remain `labdns.dev/v1alpha1` only.

## Deployment and operations

- Unchanged image posture, ports, and flags. Reload or restart onto this tag to accept over-length names in bootstrap YAML or plan/apply.
- CLI help is unchanged.

## Observability

- Unchanged.

## Compatibility and migration

- Upgrade from `v1.1.1`: rebuild/restart onto this tag. Bootstrap YAML needs no migration. Documents that were already valid keep the same Canonical JSON / `sha256:` revision.
- Documents that previously failed `invalid_name` because a label exceeded 63 octets or the presentation FQDN exceeded 254 characters now load.
- Rollback: restore the previous image/tag pin. Over-length names are rejected again on v1.1.1. Runtime mutations are discarded on restart (ADR 0003).
- Config remains `labdns.dev/v1alpha1`.

## Known limitations

See the durable list: [docs/known-limitations.md](https://github.com/hilather/go-lab-dns/blob/v1.2.0/docs/known-limitations.md).

- Over-length names cannot appear on the DNS wire. UDP/TCP still cannot pack or unpack them (ADR 0007).
- Container image is still unpublished.
- Non-ASCII / IDNA names remain rejected.
