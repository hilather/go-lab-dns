# LabDNS 1.0.0-rc.2 Release Notes

Release date: 2026-08-16
Previous release: v1.0.0-rc.1
Application version: 1.0.0-rc.2
Configuration versions: labdns.dev/v1alpha1
REST versions: /v1
MCP protocol versions: 2026-07-28
Container digest: unpublished (image build and digest pin follow this tag)

These notes are curated. They are not a commit list. They cover every functionality difference from [v1.0.0-rc.1](https://github.com/hilather/go-lab-dns/blob/v1.0.0-rc.1/docs/releases/v1.0.0-rc.1.md).

## Highlights

Second release candidate after `v1.0.0-rc.1`. Operator-visible additions are the management-listener MCP mount and the rewritten operator README. The rest is supply-chain and pipeline hardening: Go **1.26.6**, patched `golang.org/x/*` modules, SHA-pinned GitHub Actions (Dependabot PRs #21–#23, landed as SHA pins rather than floating tags), and the full `golangci-lint` v2 standard preset.

DNS, chaos, REST routes, MCP tools/resources, and the v1alpha1 schema are unchanged from rc.1 except that `labdns serve` now actually serves Streamable HTTP MCP on the management listener.

## Added

- `labdns serve` mounts the MCP Streamable HTTP adapter on the management listener at `spec.listeners.management.mcpPath` (default `/mcp`). REST and MCP share the address, bearer policy, and process lifecycle. `rest.Config.Mounts` is the adapter hook that serves extra handlers on that listener.
- Operator-facing README rewrite with YAML bootstrap, CLI validate/serve, REST and MCP state-loading examples, and a documentation map. Cinematic header (`docs/assets/header.jpg`) and 1280×640 social card (`docs/assets/social.jpg`).

## Changed

- Go 1.27 was evaluated on 2026-08-16 and deferred: only release candidates (up to `go1.27rc3`) exist. The pin stays **1.26.6** (already on the `v1.0.0-rc.1` tag SHA).
- Indirect modules: `golang.org/x/net` v0.55.0 → v0.58.0, `x/sys` v0.45.0 → v0.47.0, `x/sync` v0.20.0 → v0.22.0, `x/mod` v0.33.0 → v0.40.0, `x/tools` v0.42.0 → v0.49.0, `x/oauth2` v0.35.0 → v0.36.0. Direct dependencies remain `github.com/miekg/dns v1.1.72`, `github.com/modelcontextprotocol/go-sdk v1.7.0`, `gopkg.in/yaml.v3 v3.0.1`.
- CI and Release workflows pin `actions/checkout` v7.0.1 (`3d3c42e5aac5ba805825da76410c181273ba90b1`), `actions/setup-go` v7.0.0 (`b7ad1dad31e06c5925ef5d2fc7ad053ef454303e`), and `actions/upload-artifact` v7.0.1 (`043fb46d1a93c77aae656e7c1c64a875d1fc6a0a`). One `GO_VERSION` workflow env var feeds every job.
- `golangci-lint` v2 runs the `standard` preset again (errcheck, govet, ineffassign, staticcheck, unused). Stack leftovers from the post-rc.1 govet-only stopgap are fixed: deferred `Close` errors discarded, deprecated `parser.ParseDir` replaced by test-only `internal/testutil/goparse.ParseDir`, unused helpers removed.
- Already present on the `v1.0.0-rc.1` tag SHA (unfrozen after that tag's notes freeze, so not rc.2 deltas): Go 1.26.6, `golang.org/x/net` v0.55.0, tag-gate `release-diff.txt` under `${{ runner.temp }}`.

## Fixed

- Cache test now asserts `Original` stays empty after `Get`.
- Rate-limit burst test consumes its two tokens in separate statements.
- Classify-panic inflight test waits a full second for the follow-up SERVFAIL so a busy `go test ./...` run is not reported as a leak.
- Dependabot PRs #21 (`actions/upload-artifact` 4→7), #22 (`actions/setup-go` 5→7), and #23 (`actions/checkout` 4→7) failed `changelog` (and #22/#23 also `lint` because they forked before the govet-only stopgap). Those bumps are absorbed here as SHA pins with a changelog entry.

## Removed or deprecated

## Security

- `golang.org/x/net` is now v0.58.0 (rc.1 tag was v0.55.0, which already addressed GO-2026-5026). Go 1.26.6 was already on the rc.1 tag SHA.
- GitHub Actions run from immutable commit SHAs instead of moving major tags.
- `make security-scan` (`govulncheck`) reports no vulnerabilities on this tree.
- Authentication, authorization, refuse-forward, rate limits, secret redaction, and the three chaos emergency controls are unchanged from rc.1.

## Chaos behavior

## REST API

- No new `/v1` routes, schemas, errors, or authorization. The management HTTP server can now mount sibling handlers (used for MCP `/mcp`) without changing REST routing. OpenAPI: [api/openapi/v1.json](https://github.com/hilather/go-lab-dns/blob/v1.0.0-rc.2/api/openapi/v1.json).

## MCP API and protocol compatibility

- Protocol remains **2026-07-28 only**. SDK remains `github.com/modelcontextprotocol/go-sdk v1.7.0`. Tools, resources, prompts, and error mapping are unchanged. Manifest: [api/mcp/v1.json](https://github.com/hilather/go-lab-dns/blob/v1.0.0-rc.2/api/mcp/v1.json).
- **Behavioral fix relative to rc.1:** `labdns serve` now binds the Streamable HTTP adapter on the management listener at `mcpPath` (default `/mcp`). rc.1 documented `/mcp` but the production `serve` path did not mount it. Capability table: [api/capabilities/v1.json](https://github.com/hilather/go-lab-dns/blob/v1.0.0-rc.2/api/capabilities/v1.json).

## Configuration and schema

## Deployment and operations

- Image base remains `golang:1.26.6-alpine` → scratch, UID 65532. No port, flag, or env-var change. CLI help: [api/cli/help.txt](https://github.com/hilather/go-lab-dns/blob/v1.0.0-rc.2/api/cli/help.txt).

## Observability

## Compatibility and migration

- Upgrade from `v1.0.0-rc.1`: rebuild/restart onto this tag. Bootstrap YAML needs no migration. MCP clients that already targeted `/mcp` on the management listener now succeed against `serve` (they did not on rc.1).
- Rollback: restore the previous image digest / desired-state pin and recreate the process (ADR 0003). Runtime mutations are discarded.
- Config remains `labdns.dev/v1alpha1`. MCP clients must still send `Mcp-Protocol-Version: 2026-07-28`.
- A later `v1.0.0` tag needs its own `docs/releases/v1.0.0.md`.

## Known limitations

See the durable list: [docs/known-limitations.md](https://github.com/hilather/go-lab-dns/blob/v1.0.0-rc.2/docs/known-limitations.md).

- Container image is still unpublished; GitOps digest placeholder remains all-zero until `ghcr.io/hilather/labdns` is built from this tag and pinned.
- Durable audit is best-effort, not fail-closed.
- Absolute QPS/p99 not CI-gated; long soak is opt-in. The 24h pre-GA soak was not executed (2s CI soak only).
- Delay distributions: `fixed` and `uniform` only. DoT/DoH/DoQ, Unix-socket management, extra MCP protocol versions, and ADR 0007 malformed-wire remain out of first GA.
- Config is v1alpha1 only. Snapshot ring is one previous generation. MCP stdio is not in the production image.
