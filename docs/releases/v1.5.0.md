These notes are curated. They are not a commit list. They cover every functionality difference from [v1.4.1](https://github.com/hilather/go-lab-dns/blob/v1.4.1/docs/releases/v1.4.1.md). This change freezes the changelog and these notes. It does not create the `v1.5.0` tag.

## Breaking changes / Upgrade

Read this before restarting a process that was built from v1.4.1 or earlier. Four things break. Each one says what breaks and what to do.

**Bearer is the default.** An omitted `spec.management.auth.profile` normalizes to `bearer` in `config.Normalize` and `auth.NewPolicy` ([ADR 0011](https://github.com/hilather/go-lab-dns/blob/v1.5.0/docs/adr/0011-propose-bearer-default-profile.md)). What breaks: a config with no profile and no usable token no longer starts management. With management bound, `labdns serve` exits 1 before it listens. Stderr is `labdns serve: management auth: validation_failed: bearer profile has no usable token; set spec.management.auth.secretRef to a token file, or set profile: dev-loopback-unauth`. The same `validation_failed` sentence is the domain error. `labdns validate` exits 1 for a no-profile or other effective-`bearer` config whose `secretRef` is empty, and prints `labdns validate: validation_failed: bearer profile has no usable token; set spec.management.auth.secretRef to a token file, or set profile: dev-loopback-unauth`. Validate does not open the token file, so a `bearer` document whose `secretRef` is mounted only at runtime still validates. What to do: set `spec.management.auth.secretRef` to a token file (`openssl rand -hex 32`) and send `Authorization: Bearer` after restart, or opt out as below. `--management-listen=off` still starts with no token. The flag also treats `none`, `-`, and `unbound` as unbound.

Missing, unreadable, or empty token files fail `labdns serve` with that same sentence when the effective profile is `bearer` and management is bound. Invalid token JSON is a different error, `validation_failed: invalid token secret`.

**Loopback is no longer administrator under `profile: bearer`** ([ADR 0010](https://github.com/hilather/go-lab-dns/blob/v1.5.0/docs/adr/0010-bearer-profile-no-loopback-exception.md)). What breaks: a request from loopback (`127.0.0.0/8`, `::1`, and IPv4-mapped `127/8`, `netip.Addr.IsLoopback`) with no bearer gets 401 `authentication required`, the same as a remote peer. That includes curl, scripts, the console button "Continue as local administrator", and MCP. A config that already set `secretRef` and omitted `profile` used to treat that loopback peer as administrator; it is now `bearer`. What to do: send `Authorization: Bearer`. REST may instead use a live `labdns_session` cookie created with a bearer. MCP ignores cookies and must send the header. Health live and ready stay unauthenticated. MCP stdio `LocalOrStdio` is unchanged (no network peer). `dev-loopback-unauth` is unchanged: loopback without a bearer is still administrator, and only when the TCP peer is loopback.

**Canonical `sha256:` revisions change when the document omitted `profile`.** What breaks: v1.4.1 canonical JSON materialized an omitted profile as `dev-loopback-unauth`. v1.5.0 materializes it as `bearer`, so the `sha256:` revision changes. Plan and apply that send the old `expectedRevision` conflict. Documents that already set `profile` keep the same revision. What to do: re-GET state and use the new `expectedRevision`. `hash-v1` is unchanged: the algorithm does not hash the management profile ([ADR 0011](https://github.com/hilather/go-lab-dns/blob/v1.5.0/docs/adr/0011-propose-bearer-default-profile.md)). Its ten fields are algorithm, seed, revision, policy id, QNAME, QTYPE, client group, transport, time bucket, and nonce. A deterministic policy with an empty selector revision hashes the snapshot revision, so those draws change when this canonical revision changes. Policies that pin selector revision, and documents that already set `profile`, keep the same hash-v1 inputs.

**Opt out before upgrade to keep the old behavior.** Set `spec.management.auth.profile: dev-loopback-unauth` in the bootstrap file before you upgrade, then restart. Loopback without a bearer stays administrator. The #60 stdout warning still prints when that explicit profile is bound to an address that is not loopback. The line is written after the listening line and quotes the bound address: `labdns: warning: dev-loopback-unauth management bound to <addr> (not loopback); any loopback peer, including a same-host reverse proxy or SSH tunnel, is administrator; set profile: bearer`. Binding to loopback narrows exposure and does not remove that administrator path. `--management-listen=off`, a loopback bind, and `profile: bearer` do not warn. Reset and apply do not rebind management or reload the authenticator, so they do not warn again and the process keeps the profile it loaded at start. A later canonical document that omits `profile` stores `bearer` in the snapshot; exporting that snapshot into the bootstrap file makes the next `labdns serve` bearer.

## Highlights

v1.5.0 makes `bearer` the default management profile and removes the loopback administrator exception under that profile. Upgrade steps are in Breaking changes / Upgrade. UDP queries that arrive while every `MaxInflight` slot is taken now get a rate-capped SERVFAIL instead of a silent drop. The Go toolchain is go1.26.9. Bearer tokens shorter than 32 bytes are deprecated and v1.6.0 will refuse them; v1.5.0 still loads them.

## Added

- None. No new schema field, REST path, MCP tool, or capability row. `labdns serve` gains `--max-inflight`, `--overflow-servfail-rate`, and `--overflow-servfail-burst` (see Changed and Deployment and operations).

## Changed

- A UDP query that arrives while every `MaxInflight` slot is taken gets SERVFAIL instead of being dropped, up to `OverflowServfailRate` (default 64/s, burst 16). That budget is one global bucket shared by every client: one flooder can exhaust it, and other clients then see drops until it refills. Further surplus datagrams are dropped. The reply is built on the read loop from the header and question only (no EDNS OPT), so it is never larger than the query. QR=1, QDCOUNT other than 1, a compression pointer, a reserved label type, an overlong name, or a truncated question is still dropped. RA is 0 and AD is 0. The CD bit is copied from the query (RFC 4035 §3.2.2, RFC 6840 §5.9). A negative rate disables the replies. Set the slot cap with `labdns serve --max-inflight` or `LABDNS_MAX_INFLIGHT` (a positive integer; unset uses 1024; an explicit flag wins). Set the reply cap with `dnsserver.Config`, `labdns serve --overflow-servfail-rate` / `--overflow-servfail-burst`, or `LABDNS_OVERFLOW_SERVFAIL_RATE` / `LABDNS_OVERFLOW_SERVFAIL_BURST` (unset or 0 uses the default; an explicit flag wins over the environment). The per-source query bucket still runs first and still drops silently. TCP inflight refusal is unchanged (drop, no DNS message).
- Omitted `spec.management.auth.profile` normalizes to `bearer`. See Breaking changes / Upgrade.
- Go toolchain pinned to go1.26.9 (`go.mod` `toolchain`, CI and release `GO_VERSION`, Dockerfile `golang:1.26.9-alpine`). 1.26.0–1.26.8 lack current stdlib security fixes, most recently the Go 1.26.9 fixes (GO-2026-6603 to -6605, -6607 to -6613 and -6617 in `net/http`, `net/textproto`, `mime/multipart`, `crypto/tls` and `os`). `golang.org/x/net` moves from v0.58.0 to v0.60.0 (fixes the x/net side of GO-2026-6603, -6610, -6611, -6612 and -6617), which also pulls `golang.org/x/sys` v0.48.0. The go.mod language line is `go 1.26.0`.
- Web development dependency `source-map-js` updates from 1.2.1 to 1.2.2 (GHSA-68fv-2mgg-jv7q, high: event-loop denial of service through indexed source-map section offsets). Lockfile only (`web/package-lock.json`); `web/package.json` is unchanged. The `web/dist` build output is byte-identical, and the web CI `npm audit --audit-level=high` step passes again.
- CI workflows: `actions/upload-artifact` v7.0.1 → v7.0.2 (SHA-pinned; Dependabot #62). `actions/setup-node` v7.0.0 → v7.1.0 (SHA-pinned; Dependabot #63).

## Fixed

- UDP queries free their inflight slot before the reply is written, so a client that sends its next query as soon as it reads an answer is no longer dropped at `MaxInflight` (#64, #65: a rare `TestClassifySourcePanicIsSERVFAILAndFreesInflight` failure under parallel `-race` runs). `MaxInflight` now bounds parsing and handling, not the UDP write. TCP already released the slot before writing; unchanged.
- Erratum on [docs/releases/v1.1.0.md](v1.1.0.md): the Compose line "Loopback: Continue as local administrator" did not hold. Through the `127.0.0.1:8080:8080` publish the TCP peer is the Docker bridge, so `POST /v1/session` and `/v1` returned 401 under `dev-loopback-unauth`. Continue works only when the TCP peer is loopback.

## Removed or deprecated

- Management bearer tokens shorter than 32 bytes are deprecated. v1.5.0 does not check plain-token length when `labdns serve` reads `spec.management.auth.secretRef` at process start (auth is serve-time; reset does not reread tokens). v1.6.0 refuses a token shorter than 32 bytes at that same load. Replacement: generate tokens with `openssl rand -hex 32` (the `examples/labdns-deploy` instructions now do). v1.5.0 has no short-token log line or metric. The shared-auth (controlkit) migration adds a load-time warning (token id only) and the `labdns_auth_short_tokens_total` counter before enforcement.

## Security

- `profile: bearer` no longer treats loopback requests without a bearer as administrator. They get 401 `authentication required`. Send `Authorization: Bearer`, or sign in to the console with a token. See Breaking changes / Upgrade and [ADR 0010](https://github.com/hilather/go-lab-dns/blob/v1.5.0/docs/adr/0010-bearer-profile-no-loopback-exception.md).
- A nil management authenticator rejects every non-probe request (`authentication required`), whether or not a bearer is presented. An authenticator that does not report a profile, or that reports an empty or unknown profile, loses only the loopback-without-a-bearer administrator exception. A presented bearer is still checked by that authenticator. An omitted `spec.management.auth.profile` normalizes to `bearer` ([ADR 0011](https://github.com/hilather/go-lab-dns/blob/v1.5.0/docs/adr/0011-propose-bearer-default-profile.md)). Health probes stay unauthenticated.
- `labdns serve` prints one stdout warning after the listening line when the auth profile is explicit `dev-loopback-unauth` and the bound management address is not loopback. The line is quoted under Breaking changes / Upgrade. It says any loopback peer (including a same-host reverse proxy or SSH tunnel) is administrator, and recommends `profile: bearer`.
- Omitted profile normalizes to `bearer`. With management bound and no usable token, `labdns serve` exits before listen with the `validation_failed` sentence quoted above. `--management-listen=off` still starts with no token.
- Go 1.26.9 and `golang.org/x/net` v0.60.0 pick up the advisory fixes listed under Changed. `source-map-js` 1.2.2 fixes GHSA-68fv-2mgg-jv7q in the web lockfile (dev dependency; `web/dist` byte-identical).
- No TLS or CSP change.

## DNS behavior

- UDP overflow while `MaxInflight` is full answers SERVFAIL up to the global rate and burst, then drops. Malformed questions listed under Changed are still dropped. RA is 0, AD is 0, and CD is copied from the query. A negative `OverflowServfailRate` disables the replies. The per-source query bucket still drops silently and still runs first. TCP inflight refusal is unchanged.
- The inflight slot is released before the UDP write, so `MaxInflight` does not cover that write (#64, #65).

## Chaos behavior

- Unchanged algorithm. `hash-v1` does not hash the management profile. Draws that fall back to the snapshot revision change only when that canonical revision changes (see Breaking changes / Upgrade). No new selector, action, phase, cap, or emergency control.

## REST API

- OpenAPI (`api/openapi/v1.json`) changed in the `bearerAuth` description only. It now says loopback may omit the token under `dev-loopback-unauth` (`127.0.0.0/8`, `::1`, and IPv4-mapped `127/8`); under `profile: bearer` every peer including loopback must send the token; REST may use a live `labdns_session` cookie; health live/ready stay unauthenticated; an omitted profile normalizes to `bearer`. No new path, schema field, or status code. The 401 body is still `authentication required`.
- The SPA remains a REST client (ADR 0008).

## MCP API and protocol compatibility

- Under `profile: bearer`, MCP must send `Authorization: Bearer`. MCP ignores cookies. Stdio `LocalOrStdio` is unchanged.

## Configuration and schema

- Configuration schema file [api/jsonschema/labdns.dev.v1alpha1.json](https://github.com/hilather/go-lab-dns/blob/v1.5.0/api/jsonschema/labdns.dev.v1alpha1.json): `spec.management.auth.profile` keeps the enum `dev-loopback-unauth` and `bearer`, and gains a description that omitted normalizes to `bearer`, explicit `dev-loopback-unauth` keeps loopback-admin, and a bound management listener needs a `secretRef` token file under `bearer`. No new field. `secretRef` is still a string.
- Canonical JSON materializes omitted `profile` as `bearer`. See Breaking changes / Upgrade. Config API remains `labdns.dev/v1alpha1` only.

## Deployment and operations

- CLI help ([api/cli/help.txt](https://github.com/hilather/go-lab-dns/blob/v1.5.0/api/cli/help.txt)) lists `serve --max-inflight N`, `--overflow-servfail-rate N`, and `--overflow-servfail-burst N`. `LABDNS_MAX_INFLIGHT` sets DNS inflight slots (unset uses 1024; a set value must be a positive integer; an explicit `--max-inflight` wins). `LABDNS_OVERFLOW_SERVFAIL_RATE` (replies/s) and `LABDNS_OVERFLOW_SERVFAIL_BURST` cap the UDP SERVFAIL replies (unset or 0 uses 64 and 16; a negative rate drops those datagrams; an explicit flag wins). A burst below 0, or in (0, 1), is rejected at flag parse: `overflow SERVFAIL burst must be 0 (default) or >= 1`.
- `--management-listen=off` still starts when there is no token. `none`, `-`, and `unbound` do the same.
- Image build uses `golang:1.26.9-alpine` (was `golang:1.26.6-alpine` on v1.4.1). The image is still unpublished. Compose and Kubernetes examples still take the image from `LABDNS_IMAGE` or an untagged `ghcr.io/hilather/labdns` reference. There is no Helm chart and no app version pin in those files.
- Hashed operator-console assets (`web/dist`, `internal/web/dist/assets`) are not a `release-diff` surface.
- The #60 non-loopback warning is unchanged in wording and still applies to explicit `dev-loopback-unauth`. See Breaking changes / Upgrade.

## Observability

- `labdns_dns_admission_total{result="inflight",rcode="SERVFAIL"}` counts the overflow SERVFAIL replies. `rcode="drop"` counts the discards. The metrics catalog file is unchanged: [api/metrics/v1alpha1.json](https://github.com/hilather/go-lab-dns/blob/v1.5.0/api/metrics/v1alpha1.json). v1.5.0 has no short-token log line or metric.

## Compatibility and migration

- Upgrade from `v1.4.1`: follow Breaking changes / Upgrade. Set `secretRef` or set `profile: dev-loopback-unauth` before restart if management will be bound. Re-GET `expectedRevision` when the document omitted `profile`.
- Rollback: restore the previous image/tag pin. Runtime mutations are discarded on restart (ADR 0003). A bootstrap file edited to add `profile: dev-loopback-unauth` or `secretRef` stays edited after rollback; put the previous file back if that was only for this upgrade.
- Config remains `labdns.dev/v1alpha1`. REST remains `/v1`. MCP protocol pin remains 2026-07-28.

## Known limitations

See the durable list: [docs/known-limitations.md](https://github.com/hilather/go-lab-dns/blob/v1.5.0/docs/known-limitations.md).

- Over-length names cannot appear on the DNS wire. UDP/TCP still cannot pack or unpack them (ADR 0007).
- Container image is still unpublished.
- Non-ASCII / IDNA names remain rejected.
- The overflow SERVFAIL budget is one global bucket. One client can exhaust it.
- `dev-loopback-unauth` on a non-loopback bind still makes any loopback peer administrator, including a same-host reverse proxy or SSH tunnel. The stdout warning names that path. It does not close it.
