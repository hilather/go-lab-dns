# LabDNS 1.4.1 Release Notes

Release date: 2026-10-05
Previous release: [v1.4.0](https://github.com/hilather/go-lab-dns/blob/v1.4.1/docs/releases/v1.4.0.md)
Application version: 1.4.1
Configuration versions: labdns.dev/v1alpha1
REST versions: /v1
MCP protocol versions: 2026-07-28 (default pin; optional overlay skip)
Container digest: unpublished (image build and digest pin follow this tag)

These notes are curated. They are not a commit list. They cover every functionality difference from [v1.4.0](https://github.com/hilather/go-lab-dns/blob/v1.4.1/docs/releases/v1.4.0.md).

## Highlights

This is a notes-only patch. The Release `tag-gate` on `v1.4.0` (`36be79be`) failed with `missing release notes docs/releases/v1.4.0.md`, because the curated notes did not exist at that tag. v1.4.1 ships those notes ([docs/releases/v1.4.0.md](https://github.com/hilather/go-lab-dns/blob/v1.4.1/docs/releases/v1.4.0.md)), this file, and the frozen v1.4.0 CHANGELOG section. The application code, generated API surfaces, and behaviour are identical to v1.4.0. For the functional changes since v1.3.2 (#46–#53), read the v1.4.0 notes.

## Observability

- Unchanged from v1.4.0.

## Compatibility and migration

- Upgrading from `v1.4.0` changes nothing at runtime, and no migration is needed.
- Upgrading from `v1.3.2`: follow the Compatibility and migration section of the [v1.4.0 notes](https://github.com/hilather/go-lab-dns/blob/v1.4.1/docs/releases/v1.4.0.md). It covers the stricter chaos configuration validation, including that a positive `budget.maxFrequency` is rejected, and the REST/MCP path rules.
- Rollback: restore the previous image/tag pin. Runtime mutations are discarded on restart (ADR 0003).
- Config remains `labdns.dev/v1alpha1`.

## Known limitations

See the durable list: [docs/known-limitations.md](https://github.com/hilather/go-lab-dns/blob/v1.4.1/docs/known-limitations.md).

- Over-length names cannot appear on the DNS wire. UDP/TCP still cannot pack or unpack them (ADR 0007).
- Container image is still unpublished.
- Non-ASCII / IDNA names remain rejected.
