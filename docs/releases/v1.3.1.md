These notes are curated. They are not a commit list. They cover every functionality difference from [v1.3.0](https://github.com/hilather/go-lab-dns/blob/v1.3.0/docs/releases/v1.3.0.md).

## Highlights

Patch for overlay CNAME cache and forwarding correctness, plus two protected-name RBAC bypasses. AllowForward clients no longer reuse a refuse-forward or management-resolve CNAME-only cache hit, and suffix-only overlay CNAME now forwards using the target's policy. DNS editors can no longer drop, retarget, or wildcard-synthesize a protected name. No schema, REST path, MCP tool, or CLI change. This is a correctness patch; some observable DNS answers and denied mutations change.

## Added

- None. No new schema field, REST path, MCP tool, CLI flag, or capability row.

## Changed

- None. Defaults, flags, and public surfaces are unchanged. The Fixed items change answers and authorization outcomes that were previously incorrect.

## Fixed

- Refuse-forward (unknown / local-only) overlay CNAME answers are no longer stored under the shared local cache key. An unknown query first used to leave a CNAME-only hit that later `AllowForward` clients reused, skipping upstream Exchange until TTL expiry. Unknown and local-only clients still receive the local CNAME (RA=0). Fixes #42.
- Overlay CNAME fallthrough now forwards using the CNAME target's suffix policy when the original QNAME matches no forwarding suffix (typical suffix-only configs with no root `.` policy). Clients receive CNAME plus the upstream answer instead of a CNAME-only NOERROR. Unknown and local-only clients are unchanged. Fixes #41.
- Management `resolve` / `dns_resolve` with `useCache` no longer stores overlay `Fallthrough` results in the shared process cache. Those incomplete answers previously occupied the local cache key, so live DNS skipped forwarding and returned CNAME-only or empty NOERROR until TTL expiry. Fixes #40.
- DNS editors can no longer delete or retarget a protected name by replacing the whole zone (omitting the record) or by using a relative owner that expands to a protected FQDN. Plan/apply/validate now expand owners against the zone origin and deny zone update/remove when the current zone already contains a protected record. Fixes #38.
- DNS editors can no longer add a wildcard whose parent is an ancestor of a protected name (`*` in the same zone, or `*.lab.example.net.` when `dns.lab.example.net.` is protected). Closest-encloser synthesis would otherwise answer that QNAME without an exact owner. Fixes #39.

## Removed or deprecated

## Security

- Closes two `protected_object` RBAC bypasses for ordinary roles (including `dns-editor`). Zone update is a whole-object replace: omitting a protected record, or adding/retargeting a relative owner that expands to a protected FQDN, is now denied. A wildcard whose parent covers a protected name is also denied so closest-encloser synthesis cannot answer that QNAME. Administrators can still mutate protected objects. Shared `AuthorizeChange` (plan/apply/validate; REST and MCP).
- Refuse-forward clients still receive the local overlay CNAME only (RA=0) and do not receive leaked upstream A/AAAA from the #41/#42 paths. No authentication, TLS, or CSP change.

## DNS behavior

- Overlay CNAME may still terminate in a forwarded name. `dnsquery` now re-selects the forwarding policy on the CNAME target when the original QNAME matches no suffix (suffix-only labs with no root `.` policy). Classification and chaos still see the original-QNAME policy. Unknown and `AllowForward=false` clients never forward.
- Overlay `Fallthrough` is not cached until a forward completes. Refuse-forward overlay CNAME is returned as a complete overlay answer (`Fallthrough=false`, RA=0) but is not stored under the shared local key. Management `resolve` / `dns_resolve` with `useCache` shares that store rule.
- UDP and TCP semantics remain equivalent except for transport-specific truncation. AA/RA/AD/TC flag rules are unchanged.

## Chaos behavior

- Unchanged. Protected names still skip chaos execution. Emergency disable remains chaos-exempt. The mutation-path protected-name checks above are authorization, not chaos-engine changes.

## REST API

- Unchanged paths and schemas. No new endpoints. Plan/apply/validate (`AuthorizeChange`) now expand relative owners and deny the zone-replace and wildcard-parent cases above. The SPA remains a REST client (ADR 0008).

- Upgrade from `v1.3.0`: rebuild/restart onto this tag. Bootstrap YAML needs no migration. Canonical JSON / `sha256:` revisions of previously valid documents are unchanged.

- Rollback: restore the previous image/tag pin. The five defects return. Runtime mutations are discarded on restart (ADR 0003).
